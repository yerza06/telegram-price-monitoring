# Spec Delta

## Purpose

Определяет, кто может пользоваться ботом: владелец, заданный в конфигурации, и пользователи, которым он выдал доступ.

## ADDED Requirements

### Requirement: Администратор из конфигурации
Пользователь Telegram, чей ID равен `BOT_ADMIN_ID` из окружения, SHALL всегда иметь доступ ко всем командам бота, включая команды администратора. Запуск бота без `BOT_ADMIN_ID` SHALL завершаться ошибкой с понятным сообщением.

#### Scenario: Администратор пользуется ботом
- **WHEN** пользователь с ID, равным `BOT_ADMIN_ID`, отправляет любую команду
- **THEN** бот выполняет команду

#### Scenario: Нет BOT_ADMIN_ID
- **WHEN** бот запускается без переменной `BOT_ADMIN_ID` или с нечисловым значением
- **THEN** бот не стартует и выводит сообщение, какой переменной не хватает

### Requirement: Отказ пользователям без доступа
Бот SHALL отвечать отказом пользователю, которого нет в списке доступа и который не является администратором, и SHALL NOT выполнять его команды или сохранять его данные. В сообщении об отказе бот SHALL показывать пользователю его Telegram ID, чтобы тот мог передать его администратору.

#### Scenario: Посторонний пользователь
- **WHEN** пользователь без доступа отправляет `/add` или другую команду
- **THEN** бот отвечает, что доступа нет, показывает его Telegram ID и ничего не сохраняет

### Requirement: Выдача доступа
Администратор SHALL выдавать доступ командой `/allow <telegram_id>`. После этого пользователь SHALL пользоваться всеми командами, кроме команд администратора. Повторная выдача доступа SHALL NOT создавать дубликат.

#### Scenario: Доступ выдан
- **WHEN** администратор отправляет `/allow 123456789`
- **THEN** пользователь 123456789 получает доступ, а бот подтверждает это администратору

#### Scenario: Неверный ID
- **WHEN** администратор отправляет `/allow abc` или `/allow` без аргумента
- **THEN** бот показывает подсказку по формату команды и ничего не меняет

#### Scenario: Повторная выдача
- **WHEN** администратор выдаёт доступ пользователю, у которого доступ уже есть
- **THEN** бот сообщает, что доступ уже есть, и список доступа не меняется

### Requirement: Отзыв доступа
Администратор SHALL отзывать доступ командой `/revoke <telegram_id>`. После отзыва пользователь SHALL получать отказ, его товары SHALL удаляться из его списка, и он SHALL NOT получать уведомления. Доступ администратора отозвать SHALL NOT быть возможно.

#### Scenario: Доступ отозван
- **WHEN** администратор отправляет `/revoke 123456789` для пользователя с доступом
- **THEN** пользователь теряет доступ, его подписки на товары удаляются, бот подтверждает это

#### Scenario: Попытка отозвать доступ администратора
- **WHEN** администратор отправляет `/revoke` со своим ID
- **THEN** бот отказывает и доступ администратора сохраняется

### Requirement: Список пользователей
Администратор SHALL видеть список пользователей с доступом командой `/users`: Telegram ID, а также имя и username, если пользователь уже писал боту. Имя и username SHALL обновляться из Telegram при каждом сообщении пользователя с доступом. Команды `/allow`, `/revoke` и `/users` SHALL быть доступны только администратору.

#### Scenario: Просмотр списка
- **WHEN** администратор отправляет `/users`
- **THEN** бот показывает Telegram ID всех пользователей с доступом, с именем и username, где они известны, без самого администратора

#### Scenario: Не администратор вызывает команду администратора
- **WHEN** пользователь с доступом, но не администратор, отправляет `/allow 1`
- **THEN** бот отвечает отказом и список доступа не меняется
